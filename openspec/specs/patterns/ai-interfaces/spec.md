# AI Interface Patterns

> Design patterns for AI-powered features — chatbots, generative content, recommendations, and intelligent automation. As AI becomes embedded in every product, these patterns ensure transparency, trust, and usability.

**Category:** Patterns
**Applies to:** All platforms
**Specs in this file:** 8 requirements (REQ-AI-001 through REQ-AI-008)

---

## Requirements

---

### REQ-AI-001: AI Disclosure

**Enforcement:** `MUST` | Ethical AI, FTC Guidelines
**Platforms:** All
**Detectable:** Heuristic — check for AI disclosure labels near AI-generated content

#### Why This Matters
Users have a right to know when they're interacting with AI or viewing AI-generated content. Undisclosed AI erodes trust and may violate regulations. A simple "Generated by AI" or "AI-assisted" label is sufficient.

#### The Principle
- AI-generated content MUST be labeled as such (text, images, recommendations)
- AI chatbots/assistants MUST identify themselves as AI, not pretend to be human
- The disclosure should be visible but not obtrusive — a small label, not a modal
- Don't hide the disclosure in fine print or behind a tooltip

#### Platform Implementation Notes
- **Web:** Use a subtle badge: `<span class="ai-badge">AI-generated</span>` near the content.
- **SwiftUI:** Use a caption label below AI content with `.font(.caption)`.
- **Compose:** Use `Text("AI-generated", style = MaterialTheme.typography.labelSmall)`.
- **React Native:** Use a `Text` component with small, muted styling.

### REQ-AI-002: Processing Feedback for AI Operations

**Enforcement:** `MUST` | Nielsen's Visibility of System Status
**Platforms:** All
**Detectable:** Yes — check for loading indicators on AI-triggered operations

#### Why This Matters
AI operations (generation, analysis, search) often take 2-30 seconds — far longer than typical API calls. Without feedback, users assume the app is frozen. Show typed-out text, progress indicators, or status messages ("Analyzing your document...").

#### The Principle
- AI operations MUST show continuous feedback during processing — not just a spinner
- For text generation: stream results progressively (typed-out effect) when possible
- Show status updates for long operations: "Reading document... Analyzing patterns... Generating summary..."
- Provide a cancel/stop button for operations over 5 seconds

#### Platform Implementation Notes
- **Web:** Use streaming APIs (SSE, WebSocket) to display progressive text. Show animated dots or typing indicator.
- **SwiftUI:** Use `AsyncStream` to update UI progressively. Show `ProgressView` with description text.
- **Compose:** Use `Flow` for streaming responses. Show `LinearProgressIndicator` with status text.
- **React Native:** Use `EventSource` for SSE streaming. Animate text appearance with `LayoutAnimation`.

### REQ-AI-003: Confidence Indicators

**Enforcement:** `SHOULD` | AI UX Best Practice
**Platforms:** All
**Detectable:** Heuristic — check for confidence/certainty indicators in AI result UI

#### Why This Matters
AI predictions and suggestions have varying confidence levels. A recommendation the model is 95% confident about should feel different from one it's 40% confident about. Without confidence signals, users can't gauge how much to trust the output.

#### The Principle
- AI suggestions SHOULD indicate confidence level when accuracy varies
- Use visual weight: high confidence = prominent display, low confidence = muted/qualified
- For classification: show confidence percentage or "High/Medium/Low" label
- Don't show raw model probabilities — translate to user-friendly language

#### Platform Implementation Notes
- **Web:** Use visual styling: confident results in normal weight, uncertain results with dashed borders or lighter text. Add tooltips: "AI confidence: High".
- **SwiftUI:** Use opacity or `.foregroundStyle(.secondary)` for lower-confidence items.
- **Compose:** Use `alpha` modifier or secondary text color for uncertain results.
- **React Native:** Use `opacity` styling and secondary text colors.

### REQ-AI-004: Human Override and Edit

**Enforcement:** `MUST` | Human-in-the-Loop
**Platforms:** All
**Detectable:** Heuristic — check if AI-generated content has edit/override controls

#### Why This Matters
AI output is never 100% correct. Users MUST be able to edit, reject, or override any AI-generated content before it's finalized. AI should suggest, not dictate. Without override, users are trapped with wrong outputs.

#### The Principle
- AI-generated content MUST be editable before submission/finalization
- Provide clear "Accept" / "Edit" / "Reject" actions on AI suggestions
- AI auto-completions should be dismissible with Escape or by continuing to type
- Never auto-submit AI-generated content without user confirmation

#### Platform Implementation Notes
- **Web:** Show AI suggestions in a distinct container (dashed border, different background) with Accept/Edit/Reject buttons.
- **SwiftUI:** Use inline suggestions with `.swipeActions` for accept/reject, tap to edit.
- **Compose:** Show suggestions in `Card` with action buttons. Use `Dismissible` for swipe actions.
- **React Native:** Use an overlay/toast pattern with action buttons for AI suggestions.

### REQ-AI-005: Fallback for AI Failures

**Enforcement:** `MUST` | UX Best Practice
**Platforms:** All
**Detectable:** Heuristic — check for error handling on AI API calls

#### Why This Matters
AI services fail — rate limits, timeouts, model errors. If the AI feature fails and the UI shows nothing (or a cryptic error), users are stuck. Every AI feature needs a graceful fallback that lets users accomplish their goal manually.

#### The Principle
- AI feature failures MUST show a helpful error with a manual alternative
- "AI summary unavailable — you can read the full document below"
- Never make an AI feature the ONLY way to accomplish a task
- Retry buttons for transient failures (rate limits, timeouts)

#### Platform Implementation Notes
- **Web:** Try-catch AI API calls, show fallback UI with manual path. Include "Try again" button.
- **SwiftUI:** Use `.task` with error handling, show fallback `View` on failure.
- **Compose:** Use `LaunchedEffect` with try-catch, show fallback composable.
- **React Native:** Use error boundaries around AI features, show manual alternative.

### REQ-AI-006: AI Context and Source Attribution

**Enforcement:** `SHOULD` | Transparency, Trust
**Platforms:** All
**Detectable:** Heuristic — check for source/citation elements near AI-generated content

#### Why This Matters
When AI summarizes, recommends, or generates content, users need to know WHERE the information came from. "Based on your last 30 days of data" or "Sources: [doc1], [doc2]" builds trust and lets users verify claims.

#### The Principle
- AI summaries and analyses SHOULD cite their sources or input data
- Recommendations SHOULD explain WHY (collaborative filtering, content-based, etc.)
- Provide "Show reasoning" or "Why this suggestion?" affordance
- Don't present AI-generated facts without attribution

---

### REQ-AI-007: Rate and Cost Awareness

**Enforcement:** `SHOULD` | UX Best Practice
**Platforms:** All
**Detectable:** Heuristic — check for usage indicators near AI features

#### Why This Matters
AI features often have usage limits or costs (API tokens, generation credits). Users need to know before triggering an expensive operation, not after. "This analysis will use 1 credit (4 remaining)" prevents surprise bills and frustration.

#### The Principle
- If AI features have usage limits or costs, SHOULD show remaining quota before the action
- Show a confirmation for expensive operations: "Generate report? Uses 5 credits."
- Display usage dashboard accessible from AI feature areas
- Don't let users accidentally consume their entire quota with no warning

---

### REQ-AI-008: AI Memory and Personalization Controls

**Enforcement:** `SHOULD` | Privacy, User Control
**Platforms:** All
**Detectable:** Heuristic — check for memory/history management UI in AI features

#### Why This Matters
AI features that remember context, learn preferences, or build profiles need user controls. Users should be able to see what the AI "knows" about them, correct it, and delete it. This is both a privacy requirement (GDPR right to erasure) and a UX requirement (wrong AI context leads to bad suggestions).

#### The Principle
- Users SHOULD be able to view, edit, and delete AI memory/context about them
- Provide a "Reset AI" or "Clear history" option
- Show what data the AI is using for personalization
- Respect "don't remember this" signals
